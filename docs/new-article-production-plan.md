# 新規記事の本番公開への拡張

2026-11-25時点では選別の基礎だけをローカル実装済み。本番自動反映は引き続きObsidian記事1本だけ。以下の拡張は未配備・未承認。

## 既存記事を自動移行しない

Studioのpostに、これから新規作成した記事だけに初期設定される非表示の `publicationSystem: comfylabo-next` を追加した。既存の文書を更新する処理は含まない。公開操作や追加の承認スイッチを増やす目的ではなく、旧記事を誤って本番へ追加しないための識別情報。

`scripts/new-production-content.mjs` は固定Sanityの公開済み記事だけを匿名取得し、この識別情報を持つ記事を検証する。下書き・versions・既存のwelcomeとObsidian・重複ID／slug・危険なURL・空本文・不正日時を拒否する。対象0件は「新規記事なし」であり、本番を空にする指示にはしない。

実際の読み取り確認は対象0件。既存記事を移行対象へ追加する書き込みは0件。Studioで新規作成した文書に初期値が保存される実画面確認は今後行う。既に作られていた下書きを対象にする場合も、対象記事を確認してから扱う。

## 次の実装

1. 新規記事の一覧と本文のローカル候補を生成する。公開URL案は本文 `/posts/<slug>/`、一覧 `/readings/`。調査済みの元公開設定には、この2つの専用名前空間のルールはなかった。最終的な公開設定は実サーバーも再確認してから提案する。
2. 既存Obsidianは `/4484/` と検索・共有情報を維持する。トップと他の旧記事はそのままにする。既存ホームから新一覧へ導線を加える場合は、その変更も承認対象に含める。
3. 現在の本番用生成・受信を、Obsidianと新規記事をまとめて扱う形式へ拡張する。親 `.htaccess` を別々のCronが書き換える構造にせず、本番の設定を書き換える経路は1つにする。
4. 新形式を現行の1記事形式と明確に区別し、旧受信処理が誤って取り込まないようにする。新しい取得や生成で既存公開記事が欠けた場合は停止し、自動削除しない。
5. 隔離したApacheで一覧・本文・素材・転送・内部パス拒否、更新失敗時の正常版維持、形式移行時の復旧を検証する。現行の正常版と復旧記録を保護する。
6. 対象記事・追加URL・設定差分・停止／切り替え／復旧を具体化して、本番への拡張承認を得る。新しい記事そのもののPublishは別途対象と内容を示して確認する。

この段階では本番用workflow、Release、Xserverの受信処理／Cronを変更していない。
